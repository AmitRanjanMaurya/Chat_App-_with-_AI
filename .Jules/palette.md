## 2024-05-24 - Accessible Interactive Icons in Jetpack Compose
**Learning:** Using `Modifier.clickable` on an `Icon` component in Jetpack Compose does not automatically provide the necessary minimum touch target size (48x48dp) or visual feedback (like a ripple effect) required for good accessibility and UX.
**Action:** Always prefer wrapping `Icon` components with an `IconButton` when they are meant to be interactive. `IconButton` built-in defaults satisfy accessibility touch targets and provide focus semantics and ripple effects out of the box.
## 2026-06-04 - Accessible and Dynamic Form States & Keyboard UX
**Learning:** When using components like `IconButton`, relying solely on the `onClick` handler to block empty submissions leaves the button visually active and accessible but functionally broken. The `enabled` parameter should be used to dynamically toggle the button state, while the `tint` of the inner `Icon` must be manually adjusted (e.g. `MaterialTheme.colorScheme.onSurface.copy(alpha = 0.38f)`) to reflect the disabled state correctly. Additionally, integrating `KeyboardOptions` and `KeyboardActions` in `TextField` significantly improves the software keyboard experience by offering native send actions and capitalization formatting.
**Action:** Always dynamically tie form validation to the `enabled` state of submission buttons and provide explicit visual cues for disabled icons. Ensure `TextField` components are fully integrated with appropriate `KeyboardOptions` and `KeyboardActions` for intuitive UX.
